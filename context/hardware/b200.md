# NVIDIA B200 (SXM, sm_100) — Hardware Reference

Authoritative hardware constants for the B200 SXM Blackwell part we run on via
Modal. Use this as the ground truth for roofline math, SMEM budgets, occupancy
reasoning, and Phase-3 bottleneck diagnosis. Fields follow the schema used in
`KernelAgent/kernel_perf_agent/kernel_opt/diagnose_prompt/gpu_specs_database.py`
so any script that already understands that format can consume this block as-is.

## Derived quantities to memorize

| Quantity | Value | Where it matters |
|----------|-------|------------------|
| Arithmetic intensity crossover (fp16) | ≈ **280 FLOPs/byte** | `2250 TFLOP/s ÷ 8 TB/s` — kernels below this are bandwidth-bound, above are compute-bound |
| Arithmetic intensity crossover (fp8) | ≈ **560 FLOPs/byte** | `4500 TFLOP/s ÷ 8 TB/s` — FP8 raises the bar; scatter/gather-heavy kernels trend bandwidth-bound |
| Bytes/cycle/SM (memory) | ≈ **3.6** | `8000 GB/s ÷ 148 SMs ÷ 1.5 GHz` |
| SMEM/CTA budget (single CTA/SM) | **228 KB** | hard ceiling for `num_stages × tile_bytes` in the pipeline |
| Registers/thread (64 warps/SM) | **32** | drops quickly with low occupancy; register pressure > 64/thread halves occupancy |
| L2 round-trip cost | ~200–250 cycles | dominant when L2 hit-rate < 40 %; check `lts__t_sector_hit_rate.pct` |

## Cross-references

- SMEM budget enforcement: `bench/modal_autotune.py:46-47` (`SMEM_LIMIT = 232448`) and
  the three `smem_*` estimators (`modal_autotune.py:67-81`). Keep this file and those
  estimators in sync if either side changes.
- Stall-metric interpretation (`smsp__warp_issue_stalled_*`): see
  `bench/ncu_metrics.py` and `context/techniques/` for technique-level remedies.
- Roofline math: `arithmetic_intensity = achieved_flops / achieved_bytes`. Compare
  against the crossover above, not against peak FP32 — we run fp16 / bf16 / fp8.
