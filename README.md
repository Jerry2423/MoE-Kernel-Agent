<p align="center"><b>A three-phase agentic harness for generating high-performance Triton MoE kernels</b></p>

A specialized coding-agent harness that takes a reference PyTorch MoE implementation and produces a numerically-correct, autotuned, and class-optimized Triton kernel. Built on top of [Claude Code](https://docs.anthropic.com/en/docs/claude-code), the agent runs a strictly-gated three-phase pipeline (Learn → Implement → Optimize) and benchmarks every iteration on an NVIDIA B200 via Modal.

This harness placed **2nd in the MoE Track — Full-Agent Approach** of the [MLSys 2026 flashinfer competition (NVIDIA Track)](https://mlsys26.flashinfer.ai/).

## How it works

The agent is driven by three phase prompts in [.claude/commands/](.claude/commands/), gated by [.claude/hooks/](.claude/hooks/) that enforce per-phase write permissions and commit-message conventions.

| Phase | Reads | Writes |
|-------|-------|--------|
| **1. Learn** | `context/`, `.claude/skills/` | `knowledge/*.md` — a structured knowledge base for the MoE kernel family |
| **2. Implement** | `input/` (reference PyTorch), `knowledge/` | `solution/fused_reference.py`, `solution/subgraph_specs.json`, `solution/triton/kernel.py` (correct + frozen autotune) |
| **3. Optimize** | `solution/`, `HINTS.md` | `solution/workload_classes.json`, `solution/triton/kernel.py` (per-class wins, integrated), `ITERATIONS.md`, `iterations.jsonl` |

Each phase appends a completion block to `HANDOFF.md`. Anti-cheat invariants live in `RULES.md` and are machine-checked by `tools/check_rules.py` during Phase 2.

## Quick start

1. Place the reference PyTorch MoE implementation in `input/` and any reference materials in `context/`. The B200 benchmark and profile scripts under `bench/` are pre-configured for Modal.

2. From the repo root, launch Claude Code:

    ```bash
    claude --dangerously-skip-permissions
    ```

3. Invoke the end-to-end orchestrator:

    ```text
    /run-all
    ```

    `/run-all` runs Phases 1 → 2 → 3 in a single session, advancing `.claude/state/current_phase` between phases so the per-phase write gates remain correct. It terminates when Phase 3's existing exit rules trigger (sub-phase 3.C integration complete, stall rules, or iteration budget exhausted) and writes a final block to `HANDOFF.md`.

## Requirements

- [Claude Code](https://docs.anthropic.com/en/docs/claude-code) (we recommend Claude Opus for best results).
- A [Modal](https://modal.com/) account with access to NVIDIA B200. All benchmarking, profiling (`ncu` + `rocprof`), and autotune sweeps run remotely; no local GPU is required.
- The pre-built `fi-bench` conda environment (provides `modal`, `flashinfer-bench`, and dependencies). Do **not** create a new environment or `pip install` — a `PreToolUse` hook denies these.


## Directory layout
The `solution/triton/kernel.py` is the kernel generated by the agent.

```
TASK.md RULES.md HINTS.md HANDOFF.md ITERATIONS.md   Top-level contracts and phase state
CLAUDE.md                                            Operator's manual (always in context)
input/                                               Reference PyTorch MoE (Phase 2 input)
context/                                             Reference material + JSON schemas (Phase 1 input)
knowledge/                                           Phase 1 output
solution/                                            Phase 2 + 3 output
  fused_reference.py  fusion_notes.md                Stage 2.1
  subgraph_specs.json                                Stage 2.2
  triton/kernel.py                                   Stage 2.3 / 2.5 / 3.C — production kernel
  rules_check.{md,json}                              Stage 2.4 — anti-cheat self-audit
  autotune_notes.md                                  Stage 2.5
  workload_classes.json                              Phase 3.A
  iterations.jsonl                                   Phase 3.B — row-per-iteration log
bench/                                               Modal-driven benchmark/profile/autotune scripts
tools/                                               Validators (check_rules.py, validate_artifacts.py)
scripts/bench.sh                                     Generated by Phase 2
trajectory/                                          Per-iteration artifacts (auto-populated)
.claude/
  commands/                                          /run-all, /phase1-learn, /phase2-implement, /phase3-optimize
  hooks/                                             PreToolUse / UserPromptSubmit / Stop hooks
  skills/                                            Reusable kernel + optimization + system skills
  settings.json                                      Committed allowlist + deny + hook bindings
```

## Anti-cheat

`RULES.md` is enforced both by agent self-audit (Phase 2.4 produces `solution/rules_check.{md,json}`) and by `tools/check_rules.py`, which the Phase 2 exit gate runs. Reward-hacking attempts — delegating compute to PyTorch APIs, no-op kernels, timing-function patches, stream injection, or returning uninitialized buffers — fail the gate and block phase advancement.

## Reproducibility
The `ITERATIONS.md` and `trajectory/` artifacts provide a complete record of the agent's optimization trajectory, including all generated kernels, benchmark results, and profiling data.
